# 캐릭터 변경 회귀 검증 — 2026-10-21

캐릭터 수정 효과와 텍스처·정점 수를 유지하며 첫 수정본에서 **3,986,288 bytes(약 4.0 MB)**를 줄였습니다. 원본 대비 GLB 증가분은 **25,408,540 → 21,422,252 bytes**입니다. 18/41의 새 로더가 불필요한 밀집 morph 배열 생성을 피하도록 바꿨습니다. Chrome headless 검증은 통과했고, 공개 배포와 push는 하지 않았습니다. Safari와 저사양 실기기 검증은 미완료입니다.

## 줄인 데이터와 보존 근거

- 18/41 각각 완전히 같은 POSITION/NORMAL 데이터를 가진 중복 보정 12개를 합쳤습니다. 41의 모든 키·기본 가중치가 0인 이전 보정 2개도 제거했습니다. 각 모델에 **동작 보정 166개 + 착석 보정 1개**가 남습니다.
- 같은 보정의 계수를 합치므로 LINEAR 보간 및 혼합의 수학적 변형은 같습니다. 남긴 정점·법선의 float32 값, 기본 메시와 텍스처는 그대로입니다. 희소 인덱스를 meshopt INDICES로 압축했고 양자화는 하지 않았습니다. [18 기록](perf-review/compact-18.json), [41 기록](perf-review/compact-41.json), [18 압축 검사](perf-review/packed-18.json), [41 압축 검사](perf-review/packed-41.json).
- `office-garment-loader.js`는 명시적으로 태그된 18/41의 지원되는 형식만 처리합니다. 보정 표본을 직접 희소 배열로 읽고, 렌더링에는 착석 morph 1개만 남깁니다. 기존 helper의 보간·CPU 변형 방식은 유지했습니다. 다른 모델과 지원하지 않는 형식은 기존 경로를 사용합니다.
- 첫 수정본과 새 후보를 **366개 동작·혼합 표본**에서 비교했습니다. 모든 뼈 변환은 정확히 같고, 모든 옷 정점의 최대 차이는 **1.49×10⁻⁸ m**, 법선 성분은 **5.96×10⁻⁸**입니다. 이는 중복 계수를 합치는 연산 순서의 반올림 수준입니다. 8개 동일 각도 비교 이미지를 실제로 검수했습니다. [원시 비교](perf-review/equivalence.json), [오 대리 달리기](perf-review/equivalence-18-jog.png), [조성민 달리기](perf-review/equivalence-41-jog.png). 이미지 왼쪽은 첫 수정본, 오른쪽은 최종 후보입니다.

## 동일 조건 측정

Apple M5(10코어), RAM 16 GB, macOS 26.5.1, Chrome 155.0.8059.85 headless, 800×650/DPR 1입니다. 로컬 HTTP에서 같은 캐릭터 검사 화면·조명·카메라를 사용했습니다. 모델 응답은 no-store이며 공통 JS/CDN은 워밍된 상태입니다. 원본/첫 수정본/후보 순서를 회차마다 바꾸어 3회씩 측정했습니다. 동작별 400 ms 준비 후 2초간 프레임을 수집했고, 아래는 회차 중앙값입니다. JS heap은 명시적 GC 후 스냅샷이며 최대 메모리·OS RSS·VRAM이 아닙니다.

| 모델 | 버전 | 모델 로딩 ms | JS heap MB | helper 준비 ms |
| --- | --- | ---: | ---: | ---: |
| 18 | 원본 | 439 | 104.4 | 0 |
| 18 | 첫 수정본 | 639 | 340.8 | 44.2 |
| 18 | 최종 후보 | 503 | 154.9 | 0.1 |
| 41 | 원본 | 704 | 201.4 | 0 |
| 41 | 첫 수정본 | 953 | 420.4 | 57.9 |
| 41 | 최종 후보 | 571 | 196.4 | <0.1 |

첫 수정본 대비 heap 중앙값은 18에서 약 186 MB, 41에서 약 224 MB 감소했습니다. **18은 여전히 원본보다 약 50.5 MB를 더 씁니다.** 41의 근소한 원본 대비 감소는 모든 실행에서 보장되는 결과가 아닙니다. 회차별 범위도 [집계 JSON](perf-review/summary.json)에 보존했습니다.

정지·걷기·달리기의 프레임 간격 p95는 세 버전 모두 16.7–16.8 ms였습니다. 최종 helper의 걷기/달리기 평균 비용은 18에서 0.31/0.25 ms, 41에서 0.51/0.54 ms입니다. 전체 캐릭터 업데이트 평균은 걷기에서 원본→후보 18이 0.93→1.29 ms, 41이 1.01→1.63 ms였습니다. 옷 보정의 CPU 비용이 없어졌다는 뜻은 아닙니다.

별도로 CDP CPU 4배 지연 조건에서 원본/후보를 각 2회 측정했습니다. 걷기·달리기 프레임 간격 p95는 모두 약 33.3–33.4 ms였습니다. 후보 helper p95는 18에서 최대 1.0 ms, 41에서 최대 1.25 ms였습니다. 이 조건은 약한 GPU·낮은 메모리·열 제한이나 실제 저사양 PC를 재현하지 않습니다. [정상 CPU 원시 결과](perf-review/chrome-comparison.json), [4배 CPU 원시 결과](perf-review/chrome-cpu4.json).

## 실제 연결과 남은 한계

기본 사무실 킷·high 화질·직원 5명이 있는 v2 물류팀/경영기획팀, 체험판 물류팀, 데모 경영기획팀의 착석 로딩과 기존 이동 진단 각 180프레임을 검사했습니다. 대상 옷의 활성 보정·유한 정점/법선·자리 복귀가 통과했고 page error는 0건입니다. 다른 방 미리 받기와 선택적 복도 손님만 껐습니다. [게임 검사](perf-review/game-smoke.json). 첫 실행은 초기화 대기 120초 초과로 끝났으며, 진단을 추가한 재실행에서 같은 제품 코드로 네 경로가 통과했습니다. 최초 대기의 원인은 확정하지 못했으므로 냉시작 안정성의 증거로 사용하지 않습니다.

7개 모델의 불변 영역 감사와 helper/로더 테스트 4개가 통과했습니다. v2/체험판/데모의 모델 경로 11개 및 검수 뷰어 52/18/41/40의 정지·걷기·달리기 단추도 통과했습니다. [최종 연결 검사](final-smoke.json). 기존 216개 옷 간격 검사와 40의 정지·걷기 회귀 검사는 유지됩니다. 최종 후보의 정점 차이는 기존 최소 간격 2.54 mm보다 훨씬 작습니다. 모든 삼각형과 가능한 모든 혼합을 검사한 것은 아닙니다.

Safari 실제 게임·뷰어 검사는 **최신 화면 전환 금지 지시에 따라 보류**했습니다. 실행 거절이나 승인 대기는 아닙니다. 이 Mac에 사용할 수 있는 headless WebKit 런타임도 없었습니다. Safari/저사양 실기기 통과를 주장하지 않습니다. 남은 21.4 MB는 실제 인터넷 전송량 증가이며 이번 로컬 로딩 수치에 WAN 비용이 반영되지 않습니다. 전체 사무실 성능 최적화는 별도 작업 범위로 남깁니다.

Blender는 이번 회귀 검증에서 실행하지 않았습니다. 확인 당시 활성 Blender 프로세스는 없었고, 기존 `Blender-2026-10-21-103133.ips`에 SIGSEGV와 OpenEXR 스레드 대기 스택이 있었습니다. 이 정보만으로 반복되는 재실행 안내문의 근본 원인은 확정할 수 없습니다. 사용자 프로세스나 시스템 설정은 바꾸지 않았습니다. [확인 기록](perf-review/blender-crash-review.json).

최종 수정본은 GLB와 **두 helper 파일, office/try-office 연결, 로스터·캐시 변경을 함께** 반영해야 합니다. 공유 배포는 부모 작업의 조율 전까지 보류합니다. 수정 범위와 검증은 [수정 내역](README.md), 최종 자산 해시는 [manifest](asset-manifest.json)에 기록합니다. 커밋·전체 파일 목록은 부모에게 전달하는 로컬 인계 문서에 있습니다.
